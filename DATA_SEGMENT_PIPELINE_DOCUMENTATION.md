# Data Segment Pipeline Documentation

## Overview

This pipeline processes market trade data from the `data` folder and generates segment-based aggregation files and comparison graphs. It creates investment-based odds for different user segments (Small, Medium, Large) and compares them with price-based market odds.

## Pipeline Architecture

The pipeline consists of **two main scripts** that run sequentially:

1. **`build_segment_positions_data.py`** - Processes raw trades and creates per-user position files
2. **`build_segment_aggregation_data.py`** - Aggregates positions by segment and generates comparison graphs

---

## Step 1: Build Segment Positions (`build_segment_positions_data.py`)

### Purpose
Process raw trade data from the `data` folder and create per-user, per-market position files that will be used for segment aggregation.

### Input Structure
```
data/
├── <event_id>/
│   ├── trades/
│   │   └── <market_slug>_trades.csv
│   └── prices/
│       └── <market_slug>_price.csv (or <market_slug>_closing_prices.csv)
```

### Trade CSV Format
Expected columns in `*_trades.csv`:
- `proxyWallet` - User identifier
- `side` - Trade side (BUY/SELL)
- `size` - Trade quantity
- `timestamp` - Unix timestamp
- `slug` - Market slug
- `eventSlug` - Event identifier
- `outcome` - Token type (Yes/No)

### Price CSV Format
Two formats are supported:

**Format 1: `*_price.csv`**
- `market_slug` - Market identifier
- `price` - Price value
- `timestamp` - Unix timestamp
- `token_id` - Token identifier

**Format 2: `*_closing_prices.csv`**
- `date` - Date
- `token_type` - YES or NO
- `price` or `closing_price` - Price value

### Processing Logic

1. **Load Market Trades**
   - Read trade CSV file
   - Map columns: `proxyWallet` → `user_id`, `outcome` → `token_type` (YES/NO)
   - Convert timestamps to UTC dates
   - Filter out invalid data

2. **Compute Day Offset**
   - For each market, find the maximum date (closing date = day_offset 0)
   - Calculate day_offset: `(date - closing_date).days`
   - Earlier days have negative offsets

3. **Build Daily User Token Series**
   - Aggregate trades by: `(user_id, token_type, day_offset)`
   - Calculate:
     - `daily_buy` - Sum of BUY quantities
     - `daily_sell` - Sum of SELL quantities
     - `net_tokens` - daily_buy - daily_sell
   - Get end-of-day timestamp for each day

4. **Build Per-User Market DataFrame**
   - For each user in each market:
     - Fill all days from first trade day to closing day (day_offset 0)
     - Calculate cumulative positions:
       - `yes_cumulative_position` = cumulative sum of yes_net_tokens
       - `no_cumulative_position` = cumulative sum of no_net_tokens
     - Calculate H_y and H_n (same as cumulative positions)
     - Calculate individual positions:
       - `individual_yes_position` = H_y (if H_y > 0) + (-H_n) (if H_n < 0)
       - `individual_no_position` = H_n (if H_n > 0) + (-H_y) (if H_y < 0)

5. **Load Daily Prices** (optional, for reference)
   - Try to load `*_closing_prices.csv` first
   - If not found, try `*_price.csv` and derive daily closing prices
   - If price file has `token_id`, map to token_type using trades file
   - Forward-fill missing prices

### Output Structure
```
data_segment_output/
├── <event_id>/
│   └── <market_slug>/
│       └── user_<user_id>.csv
```

### Output CSV Format (`user_<user_id>.csv`)
Columns:
- `day_offset` - Days from closing (0 = closing day)
- `timestamp` - End-of-day timestamp
- `date` - Calendar date
- `yes_daily_buy`, `yes_daily_sell`, `yes_net_tokens`, `yes_cumulative_position`
- `no_daily_buy`, `no_daily_sell`, `no_net_tokens`, `no_cumulative_position`
- `H_y`, `H_n` - Per-market cumulative positions
- `individual_yes_position`, `individual_no_position` - Individual position calculations

## Step 2: Build Segment Aggregation (`build_segment_aggregation_data.py`)

### Purpose
Aggregate individual user positions by segment (Small, Medium, Large) and create comparison graphs showing investment-based odds vs. price-based market odds.

### Input Requirements

1. **Segment Output** (from Step 1)
   - `data_segment_output/<event_id>/<market_slug>/user_*.csv` files

2. **Segment Mapping**
   - `all_users_analysis.csv` file with columns:
     - `user_id` - User identifier
     - `user_segment` - Segment classification (Small, Medium, or Large)
     - `cumulative_total_value_max` - Maximum cumulative total value (used for segmentation)
   
   **Segment Thresholds**:
   - **Large User**: `cumulative_total_value_max` ≥ 1,000,000
   - **Medium User**: 10,000 ≤ `cumulative_total_value_max` < 1,000,000
   - **Small User**: `cumulative_total_value_max` < 10,000
   
   Note: The `user_segment` column is typically generated by running `segment_users.py` which classifies users based on their `cumulative_total_value_max` value.

3. **Price Data** (for market odds)
   - `data/<event_id>/prices/<market_slug>_price.csv` or `*_closing_prices.csv`

### Processing Logic

1. **Load Segment Mapping**
   - Read `all_users_analysis.csv`
   - Create dictionary: `user_id → user_segment`

2. **Aggregate Market Segments**
   - For each market:
     - Load all user CSV files from `data_segment_output`
     - Map each user to their segment using the segment mapping
     - For each day_offset:
       - Aggregate YES positions: Sum `individual_yes_position` for users where `yes_cumulative_position != 0`
       - Aggregate NO positions: Sum `individual_no_position` for users where `no_cumulative_position != 0`
       - Calculate odds: `agg_yes / (agg_yes + agg_no)`
     - Create 4 DataFrames:
       - `all_segments` - All users combined
       - `small_segment` - Only Small segment users
       - `medium_segment` - Only Medium segment users
       - `large_segment` - Only Large segment users

3. **Load Price Odds** (Market Odds)
   - Get market closing date from user files (day_offset = 0)
   - Load price file:
     - If `*_closing_prices.csv`: Filter YES prices, convert dates to day_offset
     - If `*_price.csv`: 
       - Map token_id to token_type using trades file
       - Filter YES prices
       - Convert timestamps to dates
       - Get end-of-day price for each date (last price by timestamp)
       - Convert dates to day_offset
   - Filter prices with day_offset <= 0 (only prices up to closing date)
   - Group by day_offset to get one price per day_offset

4. **Create Comparison Graph**
   - Plot 5 lines:
     1. **Price-based Market Odds** (blue, marker='o') - From price file YES token end-of-day prices
     2. **All Segments** (green, marker='s') - Investment-based odds from all users
     3. **Small Segment** (orange, marker='^') - Investment-based odds from Small segment
     4. **Medium Segment** (red, marker='v') - Investment-based odds from Medium segment
     5. **Large Segment** (purple, marker='d') - Investment-based odds from Large segment
   - X-axis: Day Offset (0 = Closing Day)
   - Y-axis: Odds (0 to 1)
   - Save as PNG with 300 DPI

### Output Structure
```
data_segment/
├── <event_id>/
│   └── <market_slug>/
│       ├── all_segments.csv
│       ├── small_segment.csv
│       ├── medium_segment.csv
│       ├── large_segment.csv
│       └── odds_comparison.png
```

### Output CSV Format
Each CSV file has columns:
- `day_offset` - Days from closing (0 = closing day)
- `agg_yes` - Aggregated YES positions
- `agg_no` - Aggregated NO positions
- `odds` - Calculated odds (agg_yes / (agg_yes + agg_no))

## Segment Classification

Users are classified into segments based on their `cumulative_total_value_max` value from `all_users_analysis.csv`:

- **Large User**: `cumulative_total_value_max` ≥ 1,000,000
- **Medium User**: 10,000 ≤ `cumulative_total_value_max` < 1,000,000  
- **Small User**: `cumulative_total_value_max` < 10,000

The `cumulative_total_value_max` represents the maximum cumulative total value a user has held across all markets at any point in time. This metric is calculated from the `date_group_token.csv` files generated by the main pipeline.

To generate segment classifications:
1. Run `analyze_all_users.py` to create `all_users_analysis.csv` with user statistics
2. Run `segment_users.py` to add the `user_segment` column based on the thresholds above

## Key Formulas

### Individual Position Calculation
For each user on each day:

```
H_y = yes_cumulative_position
H_n = no_cumulative_position

individual_yes_position = 
    if H_y > 0: H_y
    if H_n < 0: -H_n
    (sum both if both conditions true)

individual_no_position = 
    if H_n > 0: H_n
    if H_y < 0: -H_y
    (sum both if both conditions true)
```

### Segment Aggregation
For each segment and day_offset:

```
agg_yes = sum(individual_yes_position) for users where yes_cumulative_position != 0
agg_no = sum(individual_no_position) for users where no_cumulative_position != 0
odds = agg_yes / (agg_yes + agg_no)
```

### Day Offset Calculation
```
closing_date = max(date) in market trades
day_offset = (date - closing_date).days
```
- Closing day = day_offset 0
- Earlier days = negative day_offset

## Running the Pipeline

### Prerequisites

#### 1. Python Environment
Packages required:
- pandas >= 2.0.0
- matplotlib
- numpy

#### 2. Generate User Analysis and Segment Mappings

**Before running the segment pipeline**, you need to generate the `all_users_analysis.csv` file with segment classifications:

**Step A: Generate User Statistics**
```bash
python analyze_all_users.py
```
This creates `all_users_analysis.csv` with user statistics including `cumulative_total_value_max`.

**Step B: Classify Users into Segments**
```bash
python segment_users.py
```
This adds the `user_segment` column to `all_users_analysis.csv` based on the following thresholds:
- **Large**: `cumulative_total_value_max` ≥ 1,000,000
- **Medium**: 10,000 ≤ `cumulative_total_value_max` < 1,000,000
- **Small**: `cumulative_total_value_max` < 10,000

**Note**: The `analyze_all_users.py` script requires `date_group_token.csv` files to exist, which are typically generated by running the main pipeline (`pipeline.py`) first.

#### 3. Required Files
- `data/` folder with market trades and prices
- `all_users_analysis.csv` with `user_id` and `user_segment` columns (generated in steps above)

### Execution Steps

```bash
# Step 1: Process trades and create per-user position files
python build_segment_positions_data.py

# Step 2: Aggregate by segment and generate graphs
python build_segment_aggregation_data.py
```

### Expected Output
- `data_segment_output/` - Per-user position files
- `data_segment/` - Segment aggregations and comparison graphs

## Important Notes

1. **Day Offset Convention**: The closing day (last trading day) is always day_offset = 0. Earlier days have negative offsets.

2. **Price Loading**: The pipeline handles two price file formats:
   - `*_closing_prices.csv` with date, token_type, price
   - `*_price.csv` with timestamp, token_id, price

3. **Token ID Mapping**: When price files use `token_id`, the pipeline maps to `token_type` (YES/NO) using the trades file's `asset` and `outcome` columns.

4. **End-of-Day Prices**: For market odds, the pipeline uses the **last price of each day** (by timestamp) as the end-of-day price.

5. **Segment Filtering**: Users without a segment mapping in `all_users_analysis.csv` are excluded from segment aggregations.

6. **Position Aggregation**: Only users with non-zero cumulative positions are included in the aggregation:
   - YES positions: Only users where `yes_cumulative_position != 0`
   - NO positions: Only users where `no_cumulative_position != 0`

## Troubleshooting

### No price data loaded
- Check if price files exist in `data/<event_id>/prices/`
- Verify price file format matches expected structure
- Check if trades file exists for token_id mapping

### No segment data
- Verify `all_users_analysis.csv` exists and has correct columns
- Check if users in market have segment mappings
- Verify user CSV files exist in `data_segment_output/`

### Graph missing lines
- Check if price data was loaded (should see price-based line)
- Verify segment DataFrames are not empty
- Check if users exist in each segment for the market

## Example Workflow

1. **Prepare Data**:
   - Ensure `data/` folder has market trades and prices
   - Run main pipeline if needed to generate `date_group_token.csv` files

2. **Generate User Segments** (if not already done):
   ```bash
   python analyze_all_users.py    # Generate user statistics
   python segment_users.py         # Classify users into segments
   ```

3. **Run Step 1**:
   ```bash
   python build_segment_positions_data.py
   ```
   - Processes all markets in `data/` folder
   - Creates `data_segment_output/` with per-user files

3. **Run Step 2**:
   ```bash
   python build_segment_aggregation_data.py
   ```
   - Aggregates positions by segment
   - Generates CSV files and comparison graphs
   - Creates `data_segment/` with final outputs

4. **Verify Outputs**:
   - Check `data_segment/<event_id>/<market_slug>/` folders
   - Each should have 4 CSV files and 1 PNG graph
   - Graph should show 5 lines (1 price-based + 4 investment-based)

## Output Interpretation

### CSV Files
- `all_segments.csv`: Combined odds from all users
- `small_segment.csv`: Odds from Small segment users only
- `medium_segment.csv`: Odds from Medium segment users only
- `large_segment.csv`: Odds from Large segment users only

### Graph
- **Blue line (Price-based)**: Market odds from actual trading prices
- **Green line (All Segments)**: Investment-weighted odds from all users
- **Colored lines (Small/Medium/Large)**: Investment-weighted odds from each segment

The graph allows comparison of:
- How market prices (blue) compare to investment-weighted odds
- How different user segments (by investment size) view the market
- Whether large investors have different views than small investors
